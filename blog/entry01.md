For this, I found what's definitely the perfect app for me to practice with, known as [Swift Playground](https://developer.apple.com/swift-playground/). As the name implies, it's literally a playground for Swift, teaching the user the basics of its code and how it can be used. I've said this both in this blog and in my [Learning Logs](../tool/learning-log.md), but I have noticed some interesting parallels compared to this language and Java/JavaScript. For one, functions are here instead of the Java known Methods, but unlike JavaScript, these functions feel almost simpler:

```swift
/* Swift Function */
func introGreet(){
   let greet = "Hello World!"
   print(greet)
}

introGreet()
```

Now compared to JavaScript's, the Swift's example is definitely a bit simpler (excluding the usage of parameters in JavaScript), as the keyword for functions is shorter and the curly braces aren't required, where in JavaScript they are sometimes required:

```javascript
/* JavaScript Function */
function introGreet(name){
   document.write("Hello, " + name + "!");
}

introGreet("Bri");
```
Of course there's more things I need to learn about Swift, but not only am I still progressing through the Swift Playground lessons, but I'm also using 2 online guides I found which are the [official Swift Reference page](https://docs.swift.org/latest/documentation/the-swift-programming-language/aboutswift) and the [W3Schools Swift Guide](https://www.w3schools.com/swift/default.asp). ## Revisiting the Engineering Design Process (EDP):
Well! I don't need to define the EDP more thoroughly like I have before. However, I will list its steps again (especially as a reminder for myself) so with that said, lemme post the steps right now..

***1) Define the Problem***
***2) Research the Problem***
***3) Brainstorm possible solutions***
***4) Plan the most promising solution***
***5) Create a Prototype***
***6) Test and Evaluate the prototype***
***7) Improve as needed***
***8) Communicate the Results***

Looking at the 8 steps, I suppose I'd say I'm at Step 1 but I'm also going into Step 2? I've established the reasons I have behind wanting to create the app for sure, but I do need to think more about why other people might try to use it. An idea that quickly pops into my head could be that people who also want to learn more about the bass could use it as a good starting point. Additionally, those who want to find bass music chords more easily could also benefit from the app, as going off of my own experience, it's hard to find bass chords, especially the correct set of chords. I also had a thought that if the bass portion of this goes well, what if the app could expand to guitarists as well? Note that my top priority for this app are bass players, but maybe I could develop a section for guitarists if I have the time? With that established, I also want to see how I could get easily accessible bass chords because the search part of it will definitely be difficult. My original idea was to use a JSON that can help track some down from social media from websites such as [Music Will](https://musicwill.org/the-team). Or if I want to make this more personalized, I can find charts myself (maybe even create some) and have a smaller collection to choose from! I'm still deciding if I want this app to be more directed for myself or more directed for the general public. On the one hand, obviously it'll be beneficial to me but on the other hand, a lot of people truly fail to realize how significant bassists are to a band. They feel a lot like the backbone of a song, being there to not only support the other instruments (as all instruments do), but they also exist to add a deep and rich tone to music, really invoking all sorts of senses that, at least to me, just end up feeling so whimsical. There's still time for me to think so I'm not too worried, but with all of the content I'll be delving into this school year, I do want to ideally settle this sooner much over clunkily figuring this out in the future.
